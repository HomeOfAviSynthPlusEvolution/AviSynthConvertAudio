# AviSynth — Convert Audio

[English](README.md) | **简体中文** | [日本語](README.ja.md)

AviSynth — Convert Audio 是 AviSynthMinus 的独立音频样本格式转换模块，支持脱离 AviSynth 构建和使用，也可以通过静态链接集成到 AviSynth 核心。它提供整数 PCM 与浮点音频之间的转换，使用 Google Highway 实现跨平台 SIMD 加速，并保留普通 C 实现作为回退。

项目可以作为 Git submodule 引入 AviSynth，也支持独立测试。对外接口采用纯 C 形式，内部使用 C++ 实现，不依赖 AviSynth SDK、AvsCore 或 AvsSimd。

## 为什么拆分音频转换

音频样本转换是一项可以独立使用和验证的计算能力。将它从帧服务器核心中拆出，能够让转换算法、SIMD 实现、正确性测试和性能测试在一个范围明确的项目中维护，同时减少对宿主内部结构的依赖。

AviSynth — Convert Audio 与 AviSynthMinus 同步演进。宿主负责剪辑访问、脚本入口、元数据和音频请求，转换库负责完成输入格式到输出格式的转换。算法内部采用直接转换还是中间步骤，由转换库处理，宿主无需跟随实现细节调整调用方式。

## 支持的格式

项目支持以下五种样本格式之间的全部 20 条异格式转换路径：

| 格式 | 表示方式 |
|---|---|
| U8 | 无符号 8 位 PCM，静音值为 128。 |
| S16 | 有符号 16 位 PCM。 |
| S24 | 有符号 24 位 PCM，以三个字节按小端顺序紧密存储。 |
| S32 | 有符号 32 位 PCM。 |
| F32 | 32 位浮点音频。 |

转换保持既有 AviSynth 的数值语义，包括截断、越界饱和、NaN 转静音以及 S24 的字节布局。样本数量以单个声道的样本值计数；例如，双声道的 1024 个音频帧包含 2048 个样本值。

本项目处理样本格式转换，不承担采样率转换、声道混合或视频转换。这些功能由各自的模块维护。

## SIMD 与 CPU 限制

项目使用 Highway 生成不同 CPU 目标的转换实现，并提供独立的普通 C 回退。独立使用时，可以自动选择本机可用的实现，也可以显式选择普通 C。宿主集成时，可以查询库实际提供的目标，并在允许的范围内选择转换函数。

在 AviSynth 中，AvsSimd 负责解释环境中的 CPU 限制。最终可选目标由宿主允许的目标、硬件支持的目标和转换库实际提供的目标共同决定。`SetMaxCPU("none")` 始终使用普通 C；没有共同可用的 SIMD 目标时，也回退到普通 C。

目标选择按使用实例进行，不修改 Highway 的全局目标限制。集成接口直接使用 Highway 的目标位值；版本间缺失或无法识别的目标不参与选择，显式请求不受支持的目标会返回失败。

## 构建与集成

项目使用 CMake 构建，需要支持 C++17 的编译器。普通使用接口采用 C 类型和函数，不暴露 C++ 类、STL 容器或 Highway 向量类型，C++ 异常不会跨越接口边界。

主要集成方式是在宿主仓库中通过 Git submodule 固定本项目版本，再通过 CMake 一同构建。转换库及其依赖以静态库目标链接，由 CMake 传递依赖关系，不要求宿主直接编译或枚举内核源文件。

独立构建使用固定版本的 Highway，基线版本为 1.4.0。与宿主共同构建时，复用宿主提供的兼容 `hwy` 目标，避免重复构建依赖。AvsSimd 留在 AviSynth 仓库中，转换库直接依赖 Highway。

接口可以随 AviSynthMinus 同步演进。纯 C 接口便于集成，但不等于承诺不同版本的预编译库可以任意互换；升级时应使用相匹配的头文件和库。

链接目标为 `AviSynth::ConvertAudio`，静态库名称为 `AudioConvert`。

## 测试与性能

内核正确性测试和性能测试可以独立运行，无需加载 AviSynth。测试关注不同格式之间的转换结果、数值边界、特殊浮点输入、不规则样本数量和缓冲区边界。AviSynth 仓库中的集成测试负责验证公开滤镜入口、音频请求行为和视频透传。

截至 2026-09-06，参数化展开后的测试共 **596 项**，包括 C 接口冒烟测试；本地 Windows x64 的 MSVC、clang-cl 和纯 C 配置均全部通过。

以下为每次转换 **65,536 个样本值（64K）** 的部分 native 性能结果，耗时单位为 **μs/次调用**。基线明确限定为 **AviSynth+ 3.7.5**，不代表上游后续版本。

| 转换路径 | AviSynth+ 3.7.5 native | Convert Audio native | 加速比 |
|---|---:|---:|---:|
| S16 → F32 | 3.173 | 3.178 | 1.00× |
| F32 → S16 | 4.561 | 4.494 | 1.01× |
| S24 → F32 | 6.853 | 5.923 | 1.16× |
| F32 → S24 | 9.311 | 5.425 | 1.72× |
| S32 → F32 | 4.498 | 4.496 | 1.00× |
| F32 → S32 | 4.393 | 4.495 | 0.98× |
| U8 → S16 | 2.102 | 1.617 | 1.30× |
| U8 → S32 | 4.281 | 2.696 | 1.59× |
| S32 → U8 | 3.193 | 2.692 | 1.19× |

测量于 2026-09-06，环境为 AMD Ryzen 9 7940H、Windows x64、clang-cl 22.1.3，双方均使用 Release /O2、关闭 LTO，并固定在同一逻辑处理器上运行。原版内核取自 AviSynth+ 3.7.5（`6c7c2661`），本模块为 `16259ac5`。双方使用各自可用的 native 实现：原版按路径使用 SSE2、SSSE3 或 AVX2，本模块自动选择 Highway `AVX3_ZEN4`。

每个计时批次执行 50,000 次转换，共测量 7 轮并取各实现耗时的中位数；每批预热 100 次，轮换原版、本模块和普通 C 基线的计时顺序。全部 20 条路径在计时输入上通过逐字节结果一致性检查。原版 S24↔F32 计入经 S32 的两阶段处理，缓冲区和中间存储预先分配并重复使用。

加速比为原版耗时除以本模块耗时，大于 1 表示本模块更快。计时只包含转换内核，不包含内存分配、函数选择和宿主读取。这是一次包含七轮测量的结果快照，几个百分点的差异不宜直接视为稳定的性能优势或退步。

性能比较应使用相同的编译器、编译选项、输入数据和 CPU 限制，并明确样本数量与计时范围。内核耗时与完整滤镜耗时分别衡量，避免把宿主读取、缓冲管理等成本混入算法比较。SIMD 目标更宽并不保证每条路径都更快，具体实现以测量结果为依据。
